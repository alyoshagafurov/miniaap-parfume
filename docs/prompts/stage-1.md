## 2. CONTEXT

Клиент: ÁRUMI Parfum & Care — оптовый склад парфюма и средств ухода. Адрес: Хасавюрт,
рынок «Новый Терек». Звонки/WhatsApp: 8 928 314 40 00. Минимальный заказ от 5 000 ₽.
Отправка по всей России. Тексты бренда: «Известные бренды · Выгодные условия ·
Надёжные поставки», «ÁRUMI — ваш оптовый партнёр».

Продукт: Telegram-бот красиво приветствует клиента и открывает Mini App — каталог на
1 000+ товаров с поиском и фильтрами. Клиент собирает заявку, менеджер получает её в
Telegram. Админ сам ведёт товары, ароматы, бренды, категории — из Telegram или браузера.

Аудитория: оптовики по всей России (магазины, точки на рынках), 90% — телефон внутри
Telegram.

Категории на старте: «Парфюм 35 мл «карандаши»», «Парфюм 100 мл», «Парфюм 2 в 1
«двойняшки» 100 мл», «Дезодоранты 200 мл».

Ключевая сложность: один аромат продаётся в разных форматах/флаконах; у бренда много
ароматов; «двойняшки» содержат два аромата в одном товаре.

Стек: Next.js App Router + TypeScript strict + Tailwind v4 + Motion; PostgreSQL 16 +
Prisma; бот — grammY (TS), отдельный процесс из того же репозитория, общая БД;
Mini App — @telegram-apps/sdk-react. Хостинг (этап 3) — VPS в России, потому что
Vercel и зарубежные CDN нестабильны из РФ. api.telegram.org с российских серверов
блокируется, поэтому ВСЕ обращения к Bot API идут через настраиваемый apiRoot
(TELEGRAM_API_ROOT — релей вне РФ), бот работает в long polling. Webhook не используем.

Репозиторий пустой — это первый этап. Язык интерфейса — русский; RUB; Europe/Moscow.

## 4. USERS & SCENARIOS

**Клиент в Telegram:** /start → приветствие с фото и кнопками → «Открыть каталог» →
категория → фильтры «женский» + бренд → карточка → видит этот аромат в других форматах
→ добавляет 10 шт → в заявке видит сумму и «до минимального заказа 1 200 ₽» → оформляет
→ получает подтверждение от бота с номером.

**Клиент в браузере:** тот же путь по ссылке сайта, телефон обязателен.

**Поиск:** «шанель» находит Chanel; артикул находит товар; опечатка «шанел» тоже находит.

**Админ в Telegram:** видит кнопку «Админ-панель» (клиенты не видят) → пароль → создаёт
аромат → товар в «Парфюм 100 мл» → 3 фото → «Копия в другом формате» → публикует →
товар в каталоге.

**Админ на компьютере:** пароль + 6-значный код от бота → Excel на 300 строк →
предпросмотр с ошибками по строкам → импорт → массовая публикация.

**Менеджер:** заявка приходит в Telegram-чат (состав, сумма, контакты, кнопка «Открыть
в админке») → меняет статус.

**Ощущение:** тихая роскошь и порядок — дорогой парфюмерный бутик, где любую позицию
находишь за три касания.

**Сигнатурный ход:** «золотая нить» — тонкая золотая линия из логотипа как единственный
повторяющийся разделитель (у заголовков разделов «— Категории —», под шапкой, в
заявке) + разреженный капс в подписях (tracking 0.18–0.22em).

**Типографика:**

- дисплей — Cormorant Garamond 600, только ≥ 24px (проверь качество кириллицы;
  запасной — Playfair Display);
- текст и UI — Manrope 400/500/600;
- шкала 12/14/16/20/28/40; H1 clamp(28px, 7vw, 40px).

**Палитра:**

- фон `#F8F5EE`, поверхность `#FFFDF8`, граница `#E7E0CF`;
- текст `#23241E`, приглушённый `#6B6A5E`;
- олива `#4D5527` (бренд, CTA, активные), hover `#3F4620`;
- золото `#C9A646` — только линии и декор, НИКОГДА текст;
- ошибка `#A33A2B`; успех — олива.

**Ритм и форма:** база 4px; радиусы 10px (карточки, поля) и 999px только у чипов
фильтров; тени мягкие тёплые.

**Изображения:** фото клиента, единый кадр 4:5, светлый фон. Нет фото → заглушка с
монограммой «Á» и названием, выглядит законченно.

**Движение (этап 1):** только шиты и модалки, ease-out ≤ 250 мс.

**Telegram:** setHeaderColor / setBackgroundColor / setBottomBarColor = `#F8F5EE`;
тему Telegram не наследуем.

**Референсы по духу** (не копировать): Aesop, Le Labo, Diptyque.

**ЗАПРЕЩЕНО:** градиенты и градиентный текст (включая «золотую фольгу»),
glassmorphism, ряды одинаковых карточек с иконкой в квадратике, карточка в карточке,

## 6. ARCHITECTURE & FILES

Один пакет (pnpm), два процесса: next и бот.

```
src/app/(shop)/  — главная, c/[slug], p/[slug], b/[slug], search, cart, orders
src/app/admin/   — login, products, fragrances, brands, categories, import, orders,
                   settings, admins
src/app/api/     — только загрузка файлов и экспорт; остальное — Server Actions
src/bot/         — index.ts (точка входа pnpm bot), handlers/, keyboards/, texts/
src/server/      — db, auth/, catalog/ (запросы, поиск), orders/, import/,
                   storage/ (S3 + sharp), telegram/ (единственный клиент Bot API с
                   apiRoot, проверка initData, notify)
src/lib/         — zod-схемы, money (копейки), format ru-RU, telegram-sdk (init + dev-mock)
src/components/  — ui/ (Button, Input, Sheet, Chip, Stepper, Price, GoldRule), shop/, admin/
prisma/          — schema, миграции (включая CREATE EXTENSION pg_trgm, unaccent), seed.ts
```

Прочее: `docker-compose.yml` (postgres 16, redis 7, minio), `.env.example`, `CLAUDE.md`,
`README.md`.

**seed:** 4 категории, 8 известных брендов, 30 ароматов, 60 товаров (включая двойняшки),
с пометкой demo. `seed:bulk` — ×20 для замеров.

**CLAUDE.md:** стек, структура, команды, токены, правила — TS strict, деньги только в
копейках Int, секреты только в env, Telegram только через `src/server/telegram`,
движение по emil-design-eng, ПДн не в логах. Используй скилл coding-standards.

**Каталог:**

**Пользователи и заявки:**

- `TelegramUser {telegramId BigInt unique, firstName, username, lastSeenAt, botBlocked}`
- `Order {number ARM-000123, telegramUserId?, source TELEGRAM|WEB, name, phone, city,
delivery, comment, status, totalKop}`
- `OrderItem {productId?, снимок: sku, title, format, priceKop, qty}`

**Админы и настройки:**

- `AdminUser {telegramId, name, passwordHash argon2id, role, isActive}`
- `LoginCode {adminId, codeHash, expiresAt, attempts}`
- `Settings` — одна строка.

**Индексы:** все FK; `(categoryId, status, sortOrder)`; `(status, publishedAt)`;
GIN pg_trgm по нормализованной поисковой строке (бренд + аромат + алиасы + артикул).
Поиск — параметризованный `$queryRaw` только в `src/server/catalog`.

**Кэш витрины** — по актуальному API кэширования Next.js; `revalidateTag` при каждой
правке в админке.

**Заявка (Server Action):**

- initData проверяется подписью (`@telegram-apps/init-data-node`) либо WEB-режим;
- zod; сервер пересчитывает цены, проверяет минимум и кратность;
- rate limit 5 / 10 мин на пользователя и IP (Redis); honeypot.

**Вход админа:**

- в Telegram: подпись initData + telegramId в AdminUser + пароль;
- в браузере: пароль + одноразовый 6-значный код, который бот шлёт админу
  (TTL 5 мин, 5 попыток);
- лимит входа 5 / 15 мин; сессия httpOnly + Secure + SameSite=Lax, 12 ч.

**Файлы:**

- тип по содержимому, ≤ 10 МБ;
- sharp → WebP + AVIF (400/800/1600), EXIF удалён, случайные имена;
- S3-совместимое хранилище (S3_ENDPOINT, S3_BUCKET, S3_ACCESS_KEY, S3_SECRET_KEY,
  S3_PUBLIC_URL); dev — MinIO.

**Env:** BOT_TOKEN, BOT_USERNAME, TELEGRAM_API_ROOT (по умолчанию
`https://api.telegram.org`), ADMIN_CHAT_ID, MINI_APP_URL, DATABASE_URL, REDIS_URL,
AUTH_SECRET. Всё только в env; `.env.example` с описанием.
