## Принятые решения

### Продуктовые

- Цены видны всем по умолчанию; переключатель в Настройках. При выключении —
  «цена по запросу», заявка собирается без сумм и минимум не проверяется.
- Каталог обязан работать и вне Telegram, обычным сайтом.
- Фотографий от клиента нет: он вносит каталог сам. Заглушка с монограммой — это
  оформленное состояние, а не сбой, и она будет видна для большинства товаров.

### Технические

- `@tma.js/*` вместо `@telegram-apps/*` — и сервер, и клиент. Набор хуков
  `sdk-react` идентичен, публикации свежее на 7 месяцев, документация старого
  пакета отдаёт 404.
- Next 16.3 / Prisma 7.10 / TypeScript 5.9. RC и новые мажоры не ставим.
- Порты 3100 / 5434 / 6381 / 9100 — только dev на этой машине.
- Олива `#4D522C` снята с логотипа. `--color-control` `#858277` для границ полей.
  «Золотая нить» — две сплошные линии, без растворения (градиенты запрещены).
- Логотип временно выводится через `mix-blend-mode: multiply` — у исходника
  непрозрачный белый фон.
- Движение: правила блока 5 вручную + `check:tokens`. Скиллы Emil в этой сессии
  недоступны; `motion-ui` не используется по решению клиента.

### Готово в этой сессии

- Ревью схемы: исправлены оба high (nullable-массивы, кириллическая сортировка),
  плюс MEDIUM-HIGH (товар без аромата), MEDIUM (лишний индекс) и LOW-MED (timestamptz).
- Страж локали БД (п. 8): `src/server/db-health.ts`, вызывается из `instrumentation.ts`
  и из `boot()` бота.
- Скользящий rate-limit на Redis, fail-closed, атомарный Lua.
- Сессия на подписанной cookie, argon2id, одноразовые коды, матрица прав,
  решения входа для обоих путей — всё чистыми функциями и с тестами.
- Словарь колонок импорта и разбор строк (п. 9).

### Отложенные замечания ревью — исправить в коде, который их вводит

- **Finding 4 — `orders.totalKop` не связан с суммой позиций на уровне БД.**
  `orders_total_nonneg_chk` проверяет только `>= 0`. Пока безопасно: пишет один
  `quote.ts`, редактирования заявок нет. **Когда появится createOrder и правка заявки
  в админке** — пересчитывать `totalKop` из позиций в той же транзакции.
- **Finding 6 — BigInt `telegramId` не переживёт границу RSC.** Next не сериализует
  `bigint` ни в пропсы клиентского компонента, ни через `JSON.stringify`. **Первый же
  экран админки** со списком `TelegramUser`/`AdminUser` упадёт. Приводить
  `telegramId` к строке в DTO, не отдавать строку Prisma напрямую.
- **Каскадный пересчёт поиска.** Правка названия или алиаса бренда/аромата обязана
  пересчитать `searchText`/`searchNotes` у всех товаров, которые их денормализуют,
  **в той же транзакции**. Иначе поиск ломается так же тихо, как при записи в обход
  Prisma. Нужен тест, когда появится админский write-path.

### Найденные дефекты, которые стоит помнить

1. Сырой `CREATE INDEX` в миграции невидим для дифера Prisma — следующая миграция
   выдала `DROP INDEX` для обоих GIN-индексов. Теперь они в `schema.prisma`,
   пустая no-op миграция служит регрессионным тестом.
2. Под `LC_CTYPE=C` pg_trgm извлекает из кириллицы ноль триграмм. Опечатки
   по-русски не работали вообще, латиница работала. Теперь `C.UTF-8`.
3. `similarity()` не проходит порог для короткого запроса к длинному стогу —
   нужен `word_similarity` / `<%`.
4. Артикул в триграммном стоге совпадал со всем каталогом. Вынесен в точную ветку.
5. Prisma не ставит `NOT NULL` на List-колонки: `aliases`, `families`, `notes*` были
   nullable в БД при non-null типах в клиенте. Запись в обход Prisma клала `NULL`,
   и `buildSearchText` падал с «is not iterable».
6. Под `datcollate=C` кириллица сортируется побайтно: «ёлка» после «яблоко». Везде,
   где кириллица именно **сортируется**, нужен `COLLATE "ru-RU-x-icu"` в сыром SQL.
7. Отложенный constraint-триггер «у товара есть хотя бы один аромат» нашёл ошибку в
   собственном seed: замена связей через delete+insert шла двумя транзакциями.
