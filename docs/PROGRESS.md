## Принятые решения

### Продуктовые

- Цены видны всем по умолчанию; переключатель в Настройках. При выключении —
  «цена по запросу», заявка собирается без сумм и минимум не проверяется.
- Каталог обязан работать и вне Telegram, обычным сайтом.
- Фотографий от клиента нет: он вносит каталог сам. Заглушка с монограммой — это
  оформленное состояние, а не сбой, и она будет видна для большинства товаров.

### Технические

- `@tma.js/*` вместо `@telegram-apps/*` — и сервер, и клиент. Набор хуков
  `sdk-react` идентичен, публикации свежее на 7 месяцев, документация старого
  пакета отдаёт 404.
- Next 16.3 / Prisma 7.10 / TypeScript 5.9. RC и новые мажоры не ставим.
- Порты 3100 / 5434 / 6381 / 9100 — только dev на этой машине.
- Олива `#4D522C` снята с логотипа. `--color-control` `#858277` для границ полей.
  «Золотая нить» — две сплошные линии, без растворения (градиенты запрещены).
- Логотип временно выводится через `mix-blend-mode: multiply` — у исходника
  непрозрачный белый фон.
- Движение: правила блока 5 вручную + `check:tokens`. Скиллы Emil в этой сессии
  недоступны; `motion-ui` не используется по решению клиента.

### Готово в пятой сессии — веха D закрыта

Экраны в порядке дополнения №3, коммит после каждого.

- **Категория.** Фильтры в шите, сортировка, состояние в URL, курсорная
  подгрузка по 24. Контракт URL — один файл `src/lib/list-url.ts`, и писатель, и
  читатель: разойдись они, получился бы экран, у которого элементы управления не
  совпадают с содержимым, и ни один тип этого не ловит. Файл клиентский нарочно —
  `catalog/list.ts` тянет Prisma и клиент БД.
- **Поиск.** Те же карточки, что и в категории: сопоставление и отображение —
  два шага одного запроса, триграммный проход идёт по `products`, и только
  страница найденных id джойнится к бренду, ароматам и обложке. Подсветка
  пословная и честная: совпадение, которое не на что показать (опечатка,
  кириллический алиас латинского бренда), не подсвечивает ничего.
- **Карточка.** Свайп — это CSS scroll-snap, не библиотека. Двойняшка везде
  считается двумя ароматами: два блока «Об аромате» и отдельный список форматов
  на каждый.
- **Заявка.** Корзина и форма — один экран. Форма на react-hook-form через
  `startTransition`, не `<form action={...}>`: React сбрасывает форму действия
  безусловно и **до** вызова действия. Проверено руками — при отказе по согласию
  и при CHANGED все четыре поля остались на месте.
- **«Мои заявки».** Личность только из подписанной launch-строки, запрос
  ограничен ею в самом `WHERE`. «Повторить» собирает заявку заново из каталога,
  а не из снимка заказа, и называет то, что сегодня не купить.
- **Бренд.** Сгруппирован по формату — так этот каталог и закупают.

Проверено сборкой: все динамические маршруты — Partial Prerender, статическая
оболочка отдаётся сразу, динамическая часть стримится под скелетон.

**Не проверено:** галерея с несколькими фотографиями (в сиде фотографий нет) и
автоподгрузка по IntersectionObserver (панель браузера в этой сессии была
скрыта, кадры не идут, наблюдатель не срабатывает — кнопка «Показать ещё»
работает и проверена).

### Отложенные замечания ревью — исправить в коде, который их вводит

- **Finding 4 — закрыт для createOrder**, остаётся для правки заявки в админке:
  `totalKop` обязан пересчитываться из позиций в той же транзакции. На уровне БД
  связи по-прежнему нет.
- **Finding 6 — BigInt `telegramId` не переживёт границу RSC.** Next не сериализует
  `bigint` ни в пропсы клиентского компонента, ни через `JSON.stringify`. **Первый же
  экран админки** со списком `TelegramUser`/`AdminUser` упадёт. Приводить
  `telegramId` к строке в DTO, не отдавать строку Prisma напрямую.
- **Каскадный пересчёт поиска.** Правка названия или алиаса бренда/аромата обязана
  пересчитать `searchText`/`searchNotes` у всех товаров, которые их денормализуют,
  **в той же транзакции**. Иначе поиск ломается так же тихо, как при записи в обход
  Prisma. Нужен тест, когда появится админский write-path.

### Найденные дефекты, которые стоит помнить

1. Сырой `CREATE INDEX` в миграции невидим для дифера Prisma — следующая миграция
   выдала `DROP INDEX` для обоих GIN-индексов. Теперь они в `schema.prisma`,
   пустая no-op миграция служит регрессионным тестом.
2. Под `LC_CTYPE=C` pg_trgm извлекает из кириллицы ноль триграмм. Опечатки
   по-русски не работали вообще, латиница работала. Теперь `C.UTF-8`.
3. `similarity()` не проходит порог для короткого запроса к длинному стогу —
   нужен `word_similarity` / `<%`.
4. Артикул в триграммном стоге совпадал со всем каталогом. Вынесен в точную ветку.
5. Prisma не ставит `NOT NULL` на List-колонки: `aliases`, `families`, `notes*` были
   nullable в БД при non-null типах в клиенте. Запись в обход Prisma клала `NULL`,
   и `buildSearchText` падал с «is not iterable».
6. Под `datcollate=C` кириллица сортируется побайтно: «ёлка» после «яблоко». Везде,
   где кириллица именно **сортируется**, нужен `COLLATE "ru-RU-x-icu"` в сыром SQL.
7. Отложенный constraint-триггер «у товара есть хотя бы один аромат» нашёл ошибку в
   собственном seed: замена связей через delete+insert шла двумя транзакциями.

## Две ошибки, найденные при закрытии B

1. **`getSettings` с `'use cache'` уронил бы бота.** Бот импортирует её в пяти местах
   (`/start`, `/catalog`, `/contacts`, `/admin`, кнопка условий), а у отдельного
   процесса нет контекста запроса Next — функция бросает при первом же вызове.
   `settings.ts` теперь без импортов Next, кэширующая обёртка — в
   `settings.cached.ts`, её берут только React-компоненты. Заодно это правильно по
   сути: витрина может быть устаревшей на час, а решение «набралась ли сумма до
   минимума» — нет.
2. **`read-excel-file` v9: дефолтный экспорт возвращает массив ЛИСТОВ, не строк.**
   Под нестрогой типизацией это проходит и даёт мусор в рантайме. Нужен `readSheet`.
