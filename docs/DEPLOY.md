# Развёртывание

Для Алишера. Пошагово, от пустого сервера до работающего каталога.

Читать сверху вниз и не пропускать шаги: порядок важен в двух местах — DNS
должен быть настроен до первого запуска, а релей до того, как поднимется бот.

Что понадобится собрать заранее — в [ЧТО-НУЖНО.md](../ЧТО-НУЖНО.md).

---

## Схема

```
        покупатель                       Telegram
            │                                ▲
            │ https                          │ https
            ▼                                │
  ┌─────────────────────┐          ┌──────────────────┐
  │  VPS в России       │          │  VPS за рубежом  │
  │                     │──────────▶  релей (Caddy)   │
  │  caddy → web        │  https   └──────────────────┘
  │          bot ───────┘ через TELEGRAM_API_ROOT
  │          postgres              ┌──────────────────┐
  │          redis                 │  S3 (российский) │
  │                     ──────────▶│  фотографии      │
  └─────────────────────┘          └──────────────────┘
```

Наружу с основного сервера смотрит только Caddy — 80 и 443. Postgres, Redis,
web и bot портов на хост не публикуют вовсе.

---

## 1. Релей — сначала он

Без него бот не запустится: `api.telegram.org` с российского хостинга
недоступен.

На **зарубежном** VPS:

```bash
mkdir -p /opt/arumi-relay && cd /opt/arumi-relay
# скопируйте сюда relay/Caddyfile из репозитория
docker run -d --name arumi-relay --restart unless-stopped \
  -p 80:80 -p 443:443 \
  -e DOMAIN=relay.arumi.ru \
  -e ACME_EMAIL=вы@example.com \
  -e ALLOWED_IP=IP_ОСНОВНОГО_СЕРВЕРА \
  -v $PWD/Caddyfile:/etc/caddy/Caddyfile:ro \
  -v arumi-relay-data:/data \
  caddy:2-alpine
```

Подробности и проверка — [relay/README.md](../relay/README.md).

**Проверьте с чужой машины**, что релей закрыт:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://relay.arumi.ru/bot123/getMe
```

Должно быть `403`. Если что-то другое — `ALLOWED_IP` задан неверно, и релей
открыт всему интернету вместе с токеном бота в URL.

## 2. DNS

Две A-записи, **до** первого запуска:

| Имя              | Тип | Значение             |
| ---------------- | --- | -------------------- |
| `arumi.ru`       | A   | IP основного сервера |
| `relay.arumi.ru` | A   | IP релея             |

Проверьте, что разошлось:

```bash
dig +short arumi.ru
dig +short relay.arumi.ru
```

Пока обе команды не вернут правильные адреса, дальше идти бессмысленно: Caddy
запросит сертификат, проверка не пройдёт, и следующие попытки он будет делать
с нарастающей паузой.

## 3. Основной сервер

```bash
# Docker, если его нет
curl -fsSL https://get.docker.com | sh

mkdir -p /opt/arumi && cd /opt/arumi
git clone <адрес репозитория> .
```

### Переменные окружения

```bash
cp .env.production.example .env.production
nano .env.production
chmod 600 .env.production      # внутри токен бота и пароль базы
```

В образце описана каждая переменная и что сломается, если её не задать. Три
места, где ошибаются чаще всего:

- **`DATABASE_URL`** — хост `postgres`, а не `localhost`: приложение и база в
  разных контейнерах одной сети.
- **`TELEGRAM_API_ROOT`** — адрес релея, не `api.telegram.org`.
- **`NEXT_PUBLIC_S3_PUBLIC_URL`** — вшивается в сборку. Поменять его потом
  можно только пересборкой образа, не перезапуском.

### Бакет

Сделайте объекты бакета доступными на чтение анонимно и поставьте на них
заголовок `X-Content-Type-Options: nosniff` — заголовки приложения до чужого
origin не доходят, а браузер иначе может угадать тип файла сам.

## 4. Первый запуск

```bash
./scripts/deploy.sh
```

Одна команда, но порядок внутри неё вынужденный, и его стоит понимать.

**Сборка витрины обращается к базе по-настоящему.** Под `cacheComponents`
`next build` выполняет функции с `'use cache'`, чтобы наполнить кэш при
пререндере, — то есть идёт в PostgreSQL за настройками, категориями и лентами.
Без живой базы сборка падает с «Can't reach database server», и Suspense-границы
этого не меняют: граница решает, где окажется результат, а не будет ли он
вычислен при сборке.

Поэтому скрипт делает так: поднимает postgres и redis → ждёт healthcheck →
накатывает схему → собирает витрину (`docker build --network=host`, чтобы
сборочный контейнер увидел базу на `127.0.0.1:{POSTGRES_HOST_PORT}`) → собирает
образ бота → поднимает всё остальное.

Первая сборка занимает несколько минут.

### Проверка

```bash
docker compose -f docker-compose.prod.yml ps
# все пять — healthy

docker compose -f docker-compose.prod.yml --env-file .env.production \
  run --rm --entrypoint "" migrate pnpm deploy:check
```

Проверка запускается **внутри** сети docker, а не с хоста: в `DATABASE_URL`
стоит имя сервиса `postgres`, которое снаружи сети не резолвится. Образ
`migrate` — то же, что у бота: в нём исходники, tsx и `scripts/`.

`deploy:check` проверяет то, что ломается молча: локаль базы (под неправильной
поиск по-русски не работает, а по-латински работает — и этого не видно),
миграции, Redis, право на запись в бакет и **обе** формы пути на релее.

Он же печатает, что делать с каждой проблемой.

### Первый администратор

Образ витрины — standalone-сборка, в нём нет ни исходников, ни CLI. Все
админские команды запускаются из образа `migrate`:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production \
  run --rm --entrypoint "" migrate \
  pnpm admin:create --login magomed --telegram 123456789 \
  --name "Магомед" --role OWNER
```

Пароль печатается один раз. Сохраните и передайте лично.

### Баннер бота

```bash
pnpm brand:banner          # создаст brand/bot-banner.png, 1280×640
```

Загрузить в админке: **Настройки → Баннер приветствия бота**. Без него
приветствие — просто текст, и это тоже нормальный вид.

## 5. Настройка бота в BotFather

С аккаунта клиента, у [@BotFather](https://t.me/BotFather):

1. `/setdomain` → `arumi.ru`
2. `/setmenubutton` → кнопка «Открыть каталог» → `https://arumi.ru`

Команды (`/start`, `/catalog`, `/contacts`) бот регистрирует сам при запуске.

## 6. Обновление

```bash
cd /opt/arumi
git pull
./scripts/deploy.sh
```

Миграции накатываются автоматически перед стартом приложения. Простоя почти
нет: старые контейнеры работают, пока собираются новые.

**Перед обновлением сделайте бэкап** — см. ниже. Миграция, меняющая схему,
откатывается только восстановлением.

---

## 7. Резервные копии

### Настроить

```bash
crontab -e
```

```
10 3 * * * cd /opt/arumi && ./scripts/backup.sh >> /var/log/arumi-backup.log 2>&1
```

Дамп базы уезжает в тот же бакет, в префикс `backups/`, копии старше 14 дней
удаляются. Фотографии не дублируются: у объектного хранилища своя избыточность.

### Проверить, что копии делаются

```bash
./scripts/restore.sh        # без аргументов — покажет список копий
```

### Восстановить

```bash
./scripts/restore.sh arumi-2026-09-24T03-10-00Z.dump.gz
```

Скрипт спросит подтверждение словом, остановит web и bot, восстановит базу и
поднимет их обратно.

**Сначала потренируйтесь на копии.** Бэкап, который никто ни разу не
восстанавливал, — это надежда, а не бэкап:

```bash
docker compose -f docker-compose.prod.yml exec postgres \
  createdb -U arumi arumi_check
RESTORE_DB=arumi_check ./scripts/restore.sh <файл>
```

## 8. После того как всё заработало

Включите HSTS — но **только теперь**, когда HTTPS проверен:

```bash
# в .env.production
ENABLE_HSTS=1
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build web
```

Браузер запомнит запрет на http для этого домена на год. Включать заранее
нельзя: если с сертификатом что-то не так, откатиться будет некуда.

## Что смотреть, когда что-то не так

```bash
docker compose -f docker-compose.prod.yml logs -f web
docker compose -f docker-compose.prod.yml logs -f bot
docker compose -f docker-compose.prod.yml logs -f caddy
```

| Симптом                                                     | Обычная причина                                                                 |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Сайт не открывается, в логах Caddy ошибки ACME              | DNS ещё не разошёлся или смотрит не туда                                        |
| Бот запускается и сразу падает                              | Не отвечает релей, либо `BOT_TOKEN` неверен                                     |
| Каталог работает, бот молчит                                | Релей упал; `pnpm deploy:check` скажет точно                                    |
| Поиск не находит по-русски с опечаткой, по-латински находит | Локаль базы не UTF-8. Пересоздать базу и восстановить из дампа                  |
| Фотографии не показываются                                  | `NEXT_PUBLIC_S3_PUBLIC_URL` не совпадает с реальным origin бакета — он же в CSP |
| Заявки приходят, уведомлений нет                            | Не задан `ADMIN_CHAT_ID`                                                        |
| `web` перезапускается по кругу                              | База недоступна: healthcheck ходит в `/api/health`, который проверяет её        |
| `bot` перезапускается по кругу                              | Пульс не обновляется: бот не достучался до Telegram за три минуты               |

Логи ротируются автоматически: по 10 МБ, пять файлов на сервис.
